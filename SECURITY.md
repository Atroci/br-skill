# Política de segurança

## Relatar uma vulnerabilidade

Não publique detalhes de vulnerabilidade em issue, discussão, pull request ou
outro canal público.

Quando estiver disponível no GitHub, use o canal privado de segurança do
repositório, como Security Advisories ou private vulnerability reporting. Se
essa opção não estiver disponível, peça ao mantenedor, por um canal privado já
conhecido, um meio privado para receber o relato. Não publique os detalhes
enquanto aguarda orientação.

Envie somente o necessário para reproduzir e avaliar o problema:

- descrição do impacto e das condições necessárias;
- passos mínimos de reprodução, sem dados reais;
- versão, commit ou ambiente afetado;
- evidência redigida e uma sugestão de correção, se houver.

Não envie segredos, tokens, cookies, credenciais, PII, dados de cliente ou
documentos restritos. Não tente explorar acesso, contornar CAPTCHA ou ampliar o
impacto para obter evidência.

Esta política não publica endereço de e-mail nem prazo de resposta. A equipe
confirmará o canal e os próximos passos de forma privada.

## Escopo

O projeto trata como segurança qualquer falha que possa causar acesso não
autorizado, exposição de segredo ou PII, alteração indevida, bypass de
controle, perda de integridade ou impacto relevante para usuários, fontes ou
mantenedores.

Issues públicas servem para bugs e sugestões não sensíveis. Para decidir o
canal, consulte também `references/governanca-seguranca.md`.
